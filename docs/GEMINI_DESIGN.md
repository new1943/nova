# Gemini 建议：Nova 系统重构框架

**日期**: 2026-04-22
**来源**: Gemini 网页版

---

## 核心诊断

Nova 就像有顶级装备但动作不协调的机器——缺少统一的"神经系统"和"血液循环系统"。

---

## 五层架构设计

| 层级 | 模块 | 作用 |
|:---|:---|:---|
| **1. 唤醒与感知层** | Heartbeat | 系统的脉搏，主动性来源 |
| **2. 认知与路由层** | TopicTracker + TensionTracker + ModeRouter | 语义判别，模式路由 |
| **3. 记忆与上下文层** | 三层记忆 + MemoryBoard + Compact | 组装上下文 |
| **4. 执行与沙盒层** | QueryLoop + SideQuery + Worktree + nova_os | 工具执行闭环 |
| **5. 沉淀与进化层** | Dream + Skill 自迭代 | 夜间整理，知识进化 |

---

## 核心重构四步

| 步骤 | 解决痛点 |
|:---|:---|
| **第一步** | nova_os → QueryLoop 执行闭环（最大堵点） |
| **第二步** | 升级感知系统（废弃信号词，用语义分类） |
| **第三步** | 激活 Heartbeat + Dream |
| **第四步** | 解耦短时/长时记忆（Compact ≠ memories） |

---

## 第一步详解：执行闭环

```
LLM 输出 tool_call
    ↓
执行工具 → 获取输出
    ↓
I/O Shield 截断（~1000字符）
    ↓
追加到对话历史作为 Observation
    ↓
自动递归调用 LLM（不等待用户）
    ↓
直到 LLM 输出普通文本回复
```

---

## 第二步：感知系统升级

废弃正则表达式和信号词。

引入轻量化预处理拦截器：
- 每次用户输入后
- 主 LLM 回复前
- 过一遍轻量化分类器
- 提取话题标签（Topic）和情绪/张力（Tension）
- 注入到主 LLM 的 System Prompt 头部

---

## 第三步：Heartbeat + Dream

启动 Heartbeat 定时器。

规则：系统静默超过 2 小时，触发 Dream 进程。

Dream Prompt：
```
你是一个记忆整理专家。请分析以下今日对话日志，不要做摘要，而是提取：
1. 用户的新偏好
2. 未完成的代码逻辑
3. 值得沉淀的工具用法
将 1 和 2 更新到 MEMORY.md，将 3 喂给 Skill 自迭代系统。
```

---

## 第四步：解耦短时/长时记忆

- **Compact**：只是为了省 Token 的"临时失忆"机制（把前 10 轮废话浓缩为 1 句话留在当前 Context）
- **memories/**：必须由 Dream 模块在后台生成，存储的是有价值的"知识点"和"事件节点"，供新对话开启时检索
