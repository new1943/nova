3. TurnPipeline 执行引擎（核心）

NOVA 的 Agent 执行采用可组合的 5 阶段流水线，每一次用户输入都会经过完整流程。

graph TD A[用户输入] --> B[PolicyStage] B --> C[InjectStage] C --> D[BudgetStage] D --> E[StreamStage] E --> F[ExecuteStage] F --> G{是否继续?} G -->|是| B G -->|否| H[结束 Turn]
1. PolicyStage
根据 AgentPolicy 决定工具可见性与是否终止
2. InjectStage
注入 System Prompt、记忆、模式提示
3. BudgetStage
Token 预算检查与压缩触发
4. StreamStage
调用 LLM 进行流式响应
5. ExecuteStage
执行工具调用并处理结果

5. 重构建议（针对当前混乱）

1. 统一 Memory 注入机制

目前 MemoryBoard、DailyNotes、Recall 注入时机不统一，建议建立 MemoryLayer 的优先级和注入顺序。

2. Executor 模式标准化

5 种执行模式（ReAct/Chain/Parallel 等）应统一暴露为标准工具，并完善 WithReview 和 Project 模式。

3. 提取 Client 基类

TUI 和 Discord 客户端存在较多重复逻辑，建议抽象出 NovaClient 基类。

4. 加强错误处理与重试

目前重试策略分散在多个模块，建议在 nova-core 中统一定义 RetryPolicy。
